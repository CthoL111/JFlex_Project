## What it does
Reads a UTF-8 configuration file (`key = value`) and prints each token as
`line:column TYPE lexeme` (positions start at 1). It does not apply the settings or parse structure.

## Accepted language
- Tokens: IDENTIFIER, BOOLEAN, INTEGER, DECIMAL, STRING, ASSIGN, LBRACKET, RBRACKET (8 types)
- IDENTIFIER: letter or `_`, then letters, digits, `_` (ASCII only). Case-sensitive.
- BOOLEAN: exactly `true` or `false`
- INTEGER: digits only, no sign. DECIMAL: digits `.` digits
- STRING: `"` then any characters except `"` and line break, then `"`. No escape sequences.
- Skipped: spaces, tabs, line breaks, and comments from `#` to end of line (a `#` inside a string is part of the string)
- Errors (reported with position, **scanning continues**): ERROR_UNEXPECTED_CHAR, ERROR_UNTERMINATED_STRING (to end of line), ERROR_MALFORMED_NUMBER (e.g. `1.`)
- End of input: scanner returns null, driver prints `# end: tokens=N errors=M`
- Save files as UTF-8 without BOM.

## Known limitations
- Out of scope: arrays, nested sections like `[a.b]`, negative numbers (`-` is an error), escape sequences in strings, non-ASCII identifiers.
- The scanner does not check structure: `= = 5` gives valid tokens (a parser would reject it).
- Columns count characters, a tab counts as 1.
- Tests were written and expected outputs were checked with a separate model; record your own actual results in `tests/results.md`.
